## 優先度P0 — データの正確性・欠落防止

### P0-1：全限月取得の完全性を検証してから保存する <badge>完了 2026-11-05</badge>

現状：
- `get_option_data.py` は限月ごとの取得例外を捕捉して次へ進みます。
- `all_records` が空でなければ処理が続くため、一部限月だけのデータで最新CSVが更新される可能性があります。

改善：
- 期待する3限月がすべて取得できたことを必須化
- 各限月にCALL・PUTが存在することを検証
- Strike件数・範囲・重複を検証
- 検証失敗時は既存latest.csvを保持
- 一時ファイルへ書き、検証後に置換する

### P0-2：空欄とゼロを分離する（完了：2026-11-05）

現状：
- Pythonの数値変換関数とHTMLの `num()` は空欄を0に変換します。
- 未取得と実際のゼロが混同されます。

改善：
- 欠損値をNone相当で保持
- 差分計算は両方の値が有効な場合だけ実行
- HTMLでも欠損は「—」や「未取得」と表示
- OI不完全時はMax Painを無効化

### P0-3：取引日をまたぐ出来高差分を防止する（完了：2026-11-05）

現状：
- 差分キーは限月・CALL/PUT・Strikeで、取引日を含みません。

改善：
- 取引日が一致するデータだけで出来高差分を計算
- 取引日切替時は新しい基準値を設定
- 初回値を増加アラートとして扱わない

### P0-4：Max Painのデータ完全性を検証する

現状：
- HTML側にOIが不完全な状態を厳密に判定する仕組みがありません。
- 空欄が0に変換されると、欠損状態でMax Painが計算される可能性があります。

改善：
- CALL・PUT双方のOI取得状態を検証
- 期待Strikeの欠損を検知
- 不完全なら数値を出さず「OI未取得／不完全」と表示
- 計算対象限月・使用件数・最終更新時刻を表示

## 優先度P1 — 通知の信頼性・ルール統一

### P1-1：通知失敗を再送できるようにする

現状：
- 現行処理は通知送信後にlatest.csvを更新します。
- 送信失敗後も処理が続くと、次回差分が消えて再通知できない可能性があります。
- 1回の通知上限は20件で、超過分をキューへ残す仕組みは確認できません。

改善：
- 通知候補を永続キューへ保存
- Discord送信成功を確認してから送信済みにする
- 失敗分・上限超過分は次回へ持ち越す
- 重複通知防止キーを統一する

### P1-2：通知ロジックを統合する

現状：
- `get_option_data.py` に現行通知処理が存在します。
- `calculate_difference.py`、`detect_large_trades.py`、`notify_discord.py` にも別系統の処理があります。
- 閾値・計算・通知済み管理が複数箇所に分散しています。
- 独立スクリプト3本は現在のworkflowから呼び出されていません。

改善：
- 共通の差分データ仕様を定義
- 通知条件を1か所で管理
- 価格・出来高・OI・IV・売買代金の閾値を仕様書へ集約
- 現行処理に必要な機能を移植した後、未使用コードを整理
- 既存の通知履歴を安全に移行する

### P1-3：Discord Webhookのworkflow連携を確認する

現状：
- Pythonコードは `DISCORD_WEBHOOK_URL` 環境変数を参照します。
- 現行workflowのYAMLにはSecretsを環境変数として渡す記述が確認できません。

改善：
- GitHub Secretsの登録状態を確認
- workflowの実行stepへ安全に環境変数を渡す
- Webhook URLをログへ出さない
- 未設定時は通知未設定を明示して処理結果に記録する

## 優先度P2 — HTML・操作性

### P2-1：現在値の取得・表示

現状：
- HTMLに現在値表示欄はありますが、現在値を設定する処理が確認できません。

### P2-2：更新状態の明確化

現状：
- 更新ボタンはActions workflowページを開きます。

改善：
- ボタンの動作を「Actionsを開く」等と明示
- データ取得時刻とQRI更新時刻を分けて表示
- 古いデータ・取得失敗・取得中を区別

### P2-3：HTMLの欠損表示

- 空欄をゼロ表示しない
- OI・出来高の取得率を表示
- 限月ごとのデータ状態を表示
- Max Painの有効／無効状態を明確化
