# 改善課題・優先順位

最終更新日：2026-11-09  
対象：mainブランチのコード・workflow・HTML・CSV

この文書は、実装済みの改善と未対応課題を区別して管理します。完了と記載した項目はコード変更とGitHub Actionsでのテストを確認済みです。

## 優先度P0 — データの正確性・欠落防止

### P0-1：全限月取得の完全性を検証してから保存する（完了：2026-11-05）

実装内容：
- 期待する3限月すべての取得成功を必須化
- 各限月の各StrikeにCALL・PUTが各1件あることを検証
- 重複レコード・想定外限月・空の限月を拒否
- 検証失敗時は latest.csv・differences.csv・日次履歴の更新へ進まない
- latest.csv は一時ファイルへ書き出し、flush/fsync後に os.replace で置換
- tests/test_data_validation.py にテストを追加

残課題：
- Strike数の急減・異常なStrike範囲の検知は未実装。QRI側の仕様変更と区別するため、限月ごとの件数・範囲を継続記録して比較する。

### P0-2：空欄とゼロを分離する（完了：2026-11-05）

実装内容：
- Pythonの数値変換は欠損値をNone相当で保持し、数値0と区別
- 前回・今回の両方が有効な数値の場合だけ差分を計算
- 欠損値を含む項目から誤った差分アラートを生成しない
- HTMLでは欠損を「—」と表示し、棒グラフの幅は0として描画
- OIが1つでも欠損している場合、Max Pain・OI合計・OI比率を計算しない
- NaN・Infinityも欠損値として扱う

残課題：
- 画面とログに欠損件数・欠損率を表示する。

### P0-3：取引日をまたぐ出来高差分を防止する（完了：2026-11-05）

実装内容：
- 行照合キーは (contract, option_type, strike)
- 出来高差分は前回・今回の trading_day が両方存在し、一致する場合だけ計算
- 取引日切替時や日付不明時は出来高差分を欠損値として扱い、出来高アラートを抑止
- OI・価格・板数量は、前回・今回の値が有効な数値の場合だけ差分を計算
- 同一取引日と取引日切替のテストを追加

残課題：
- OIについて、日次公表値の変化と日中変化を区別するルールを別途定義する。

### P0-4：Max Painのデータ完全性を検証する（一部完了：2026-11-05）

実装済み：
- StrikeごとのCALL/PUT行数を検査し、片側欠損を検出
- 同一Strike・同一種別の重複行、不正Strike・不正種別を検出
- CALL OI・PUT OIの取得数と取得率を画面に表示
- OIが一部欠損していても、取得できているStrike単位のOIは表示し、欠損セルだけ「—」にする
- CALL OI・PUT OIの取得数を別々に表示し、取得処理ログにも限月別の取得数を記録
- ペアまたはOIが不完全な場合はMax Pain・OI合計・OI比率を更新しない
- 実際のHTML内JavaScript関数をNode.jsでテスト

未対応・制約：
- CALLとPUTの両方の行が同じStrikeで丸ごと欠けた場合、現状は検知できない
- 検知にはQRIの期待Strike一覧、または正しいStrike範囲を定義できる根拠データが必要
- 現在はStrike間隔を推測して欠落Strikeを決めつけない

## 優先度P1 — 通知の信頼性・ルール統一

### P1-1：通知失敗を再送できるようにする

現状：
- Discord送信失敗後も最新CSVが更新されると、次回差分が消えて再通知できない可能性がある
- 1回の通知上限は20件で、超過分をキューへ残す仕組みがない

改善：
- 通知候補を永続キューへ保存
- Discord送信成功を確認してから送信済みにする
- 失敗分・上限超過分は次回へ持ち越す
- 重複通知防止キーを統一する

### P1-2：通知ロジックを統合する

現状：
- get_option_data.py に現行通知処理がある
- calculate_difference.py、detect_large_trades.py、notify_discord.py にも別系統の処理がある
- 独立スクリプト3本は現在のworkflowから呼び出されていない

改善：
- 共通の差分データ仕様を定義
- 通知条件・閾値を1か所で管理
- 現行処理に必要な機能を移植した後、未使用コードを整理
- 既存の通知履歴を安全に移行する

### P1-3：Discord Webhookのworkflow連携を確認する

現状：
- Pythonコードは DISCORD_WEBHOOK_URL 環境変数を参照
- 現行workflowのYAMLにはSecretsを環境変数へ渡す記述がない
- 直近のActionsログでもWebhook URL未設定を確認

改善：
- GitHub Secretsの登録状態を確認
- workflowの実行stepへ安全に環境変数を渡す
- Webhook URLをログへ出さない
- 未設定時は通知未設定を明示する
