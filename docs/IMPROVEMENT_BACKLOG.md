最終更新日：2026-11-11  
対象：mainブランチのコード・workflow・HTML・CSV

この文書は、実装済みの改善と未対応課題を区別して管理します。完了と記載した項目はコード変更とGitHub Actionsでのテストを確認済みです。

## 優先度P0 — データの正確性・欠落防止

### P0-1：全限月取得の完全性を検証してから保存する（完了：2026-11-05）

実装内容：
- 期待する3限月すべての取得成功を必須化
- 各限月の各StrikeにCALL・PUTが各1件あることを検証
- 重複レコード・想定外限月・空の限月を拒否
- 検証失敗時は latest.csv・differences.csv・日次履歴の更新へ進まない
- latest.csv は一時ファイルへ書き出し、flush/fsync後に os.replace で置換
- tests/test_data_validation.py にテストを追加

残課題：
- Strike数の急減・異常なStrike範囲の検知は未実装。QRI側の仕様変更と区別するため、限月ごとの件数・範囲を継続記録して比較する。

### P0-2：空欄とゼロを分離する（完了：2026-11-05）

実装内容：
- Pythonの数値変換は欠損値をNone相当で保持し、数値0と区別
- 前回・今回の両方が有効な数値の場合だけ差分を計算
- 欠損値を含む項目から誤った差分アラートを生成しない
- HTMLでは欠損を「—」と表示し、棒グラフの幅は0として描画
- OIに真の空欄・解析不能が1つでもある場合、Max Pain・OI合計・OI比率を計算しない。QRIハイフンは照合に基づき0扱いとし、原表状態を保持
- NaN・Infinityも欠損値として扱う

残課題：
- 画面とログに欠損件数・欠損率を表示する。

### P0-3：取引日をまたぐ出来高差分を防止する（完了：2026-11-05）

実装内容：
- 行照合キーは (contract, option_type, strike)
- 出来高差分は前回・今回の trading_day が両方存在し、一致する場合だけ計算
- 取引日切替時や日付不明時は出来高差分を欠損値として扱い、出来高アラートを抑止
- OI・価格・板数量は、前回・今回の値が有効な数値の場合だけ差分を計算
- 同一取引日と取引日切替のテストを追加

残課題：
- OIについて、日次公表値の変化と日中変化を区別するルールを別途定義する。

### P0-4：Max Painのデータ完全性を検証する（一部完了：2026-11-09）

実装済み：
- StrikeごとのCALL/PUT行数、重複行、不正Strike・不正種別を検査
- QRIのOIセルを数値・ハイフン・空文字・解析不能に分類
- `open_interest_status` 列を追加し、QRI原表の状態をCSVに保持
- JPX日次建玉データ由来の公開表との複数Strike照合に基づき、QRIの「-」を暫定的に0として集計
- HTMLにCALL/PUT別のQRIハイフン件数を表示
- OI数値が全Strikeで揃う場合はMax Pain・OI合計・OI比率を計算
- 空セル・解析不能・ペア不完全・重複・不正行があれば集計を停止
- PythonとHTML JavaScriptの自動テストを実装

確認結果（2026-11-09 11:15 QRI更新）：
- 2026-11限：CALL 240/240、PUT 240/240。ハイフンはCALL 101、PUT 70
- 2026-12限：CALL 348/348、PUT 348/348。ハイフンはCALL 184、PUT 130
- 2027-03限：CALL 121/121、PUT 121/121。ハイフンはCALL 83、PUT 58
- 3限月合計1,418レコードでOI空欄0件。ハイフン626件は0として計算し、原表状態を保持
- GitHub Actionsで17テスト成功

未対応・制約：
- QRI自身の仕様説明で「-」の意味を明記した資料は未確認。JPX日次建玉データ由来の公開表との複数Strike照合に基づく暫定解釈であり、引き続き原本との照合を行う
- CALLとPUTの両方の行が同じStrikeで丸ごと欠けた場合、現状は検知できない。検知にはQRIの期待Strike一覧または信頼できる基準データが必要
- Strike間隔を推測して欠落Strikeを決めつけない

## 優先度P2 — HTML・操作性

### P2-1：現在値の取得・表示・ATM判定（完了：2026-11-11）

実装内容：
- QRI `#priceInfo` の「日経平均株価 (日経225)」行から現物指数価格と、その値に併記された時刻を取得
- 日経225先物とは別項目として扱い、ATM判定には日経平均株価を使用
- `underlying_current_price` / `underlying_price_time` を最新CSV・履歴CSVへ保存
- 3限月ページ間で価格・時刻が一致しない場合や欠落時はスナップショットを保存しない
- HTML上部に価格とQRI時刻を表示
- 選択限月の全Strikeから最も近いStrikeをATMとして緑色表示。表示範囲の絞り込み前に判定
- Max Painはオレンジ色、同一StrikeならATM/Max Pain両方のマーカーを表示

確認・制約：
- `underlying_price_time` はQRI表示の月/日・時:分をそのまま保存する。取得時刻 `collected_at` とは異なる
- QRIの参考価格表構造が変わり、価格・時刻を解析できない場合は安全側に倒して保存を停止する

### P2-2：更新状態の明確化

- 更新ボタンの動作を「Actionsを開く」等と明示
- データ取得時刻とQRI更新時刻を分けて表示
- 古いデータ・取得失敗・取得中を区別

### P2-4：Volume・OIバーの共通尺度（完了：2026-11-11）

実装内容：
- CALL Volume・CALL OI・PUT OI・PUT Volumeの4系列で共通の最大値を使用してバー幅を正規化
- 最大値は選択限月の全Strikeから計算し、表示範囲の絞り込み後のデータで再計算しない
- 全Strike／中央±5,000／中央±2,500の切替で、同じ数値のバー幅が変わらないように修正
- ユーザーによる画面確認でCALL VolumeとCALL OIの長さの不整合が解消したことを確認
- GitHub Pagesビルド（run 42975419036）が成功

仕様上の注意：
- 尺度は限月ごとに独立しています。異なる限月間のバー長を絶対値比較に使わないでください。
- 欠損値は幅0として描画しますが、データ値を0に置き換えるものではありません。
